# lvgl帧率优化

版本：1.0.0。用于诊断和优化 LVGL 动画与界面实际帧率的项目技能。

显示名称为 **lvgl帧率优化**；工具调用标识和安装目录为 `lvgl-fps-optimization`。

## 适用范围

适用于已经使用 LVGL、需要定位卡顿或优化实际交付帧率的嵌入式图形界面项目。本技能提供测量、优化决策和验收流程；具体驱动与加速实现按目标工程适配。

### 平台与系统类型

| 类型 | 典型工程 | 可使用的方法 | 适配与验证要求 |
| --- | --- | --- | --- |
| MCU + RTOS | ESP32、STM32 等搭配 FreeRTOS 或其他 RTOS 的屏幕项目 | 分析绘制/传输瓶颈、内存与带宽、双缓冲、刷新节拍及资源生命周期 | 按芯片核实 DMA/PPA/DMA2D 能力、cache 同步、任务调度和显示端口 |
| MCU 裸机 | 已移植 LVGL，使用主循环或中断提供 tick 的项目 | 帧预算、重绘范围、素材格式、缓冲所有权及帧完成时间戳分析 | 核实 tick、刷新调度与传输完成事件；RTOS 任务清理方法不直接适用 |
| 嵌入式 Linux | 使用 LVGL 的仪表盘、工业 HMI、控制面板和触摸终端 | 区分绘制、搬运、显示等待，检查实际呈现节拍和退出资源释放 | 对接实际显示后端的完成/呈现事件，GPU 与显示资源由对应后端管理 |
| PC 模拟器 | LVGL + SDL 的开发和回归环境 | 固定时间截图、视觉对比、生命周期及边界调用检查 | PC 结果用于逻辑与视觉验证，板端 FPS、带宽和花屏须实机验证 |

### 适合处理的场景

- **动画与界面卡顿：** 开屏、页面切换、图片缩放、透明度渐变、多图层混合、扫光或遮罩。
- **实际刷新不稳定：** 平均 FPS 偏低、偶发长帧、漏帧，或面板标称60Hz但动画仍不流畅。
- **绘制与传输开销偏高：** 大图、全屏重绘、重复拷贝、PSRAM 访问及多个外设争用带宽。
- **结束后仍占资源：** 动画退出后任务或定时器持续运行、内存下降、重复启动或删除 parent 时崩溃。
- **需要可复现验收：** 分别验证帧节拍、整段平均 FPS、阶段时序、图像一致性、内存及空闲 CPU。

### 屏幕、色深与加速条件

MIPI DSI、RGB、SPI 等接口均可参考本技能的定位方法；采样点必须对应实际驱动的传输完成或显示呈现事件。同步阻塞与异步传输端口采用不同的节拍方案，不能统一套用1ms刷新周期。

RGB565、ARGB8888、带 alpha 的素材等格式需根据显示端口和内存预算选择。DMA、PPA、DMA2D 或 GPU 可作为优化选项；没有硬件加速时，仍可使用减少重绘、素材优化和传输路径精简等方法。固定背景可考虑离线缓存，实时业务数据与交互内容应保留动态绘制。

### 已验证环境与迁移边界

本技能的实机经验来自 **ESP32-P4 + FreeRTOS + ESP-IDF 5.5.4 + LVGL 9.2.2 + esp_lvgl_port 2.6.3 + MIPI DSI + 1024×600 RGB565**，配合 PSRAM、内部 SRAM 分块及 DMA2D；另有 PC/SDL 生命周期与视觉对照。详见 [案例与迁移边界](references/esp32p4-case.md)，其中也列出了未通过或未执行的验收项。

其他芯片、系统、屏幕接口及 LVGL 版本属于方法可迁移范围，尚未逐个平台实测。使用前检查当前工程的 API、驱动和依赖实现；案例中的初始化表、私有补丁、显存交接与熄屏顺序不可直接照搬。可按30/50/60 FPS等目标设置帧预算，最终能否达标取决于分辨率、接口带宽、画面复杂度及并发负载。

持续花屏时先验证面板与链路正确性；单独的时间戳脚本 PASS 也不能替代视觉、内存和硬件验收。本技能面向 LVGL 工程，其他 GUI 框架需要另行适配。

## 安装到项目

在项目根目录运行：

```sh
git clone --branch v1.0.0 --depth 1 https://github.com/squid-232/lvgl-fps-optimization.git .agents/skills/lvgl-fps-optimization
```

也可以下载 Release 中的 `lvgl-fps-optimization-v1.0.0.zip`，将其中的 `lvgl-fps-optimization` 文件夹解压到项目的 `.agents/skills/` 下。已有同名目录时先比较并备份本地修改。重新打开项目或新建会话后使用：

```text
使用 $lvgl-fps-optimization 分析本项目的实际帧率瓶颈，实施优化并验证帧节拍、视觉与资源释放。
```

## 工作方法

1. 固定屏幕版本、初始化表和背光顺序，先消除花屏、闪屏。
2. 分别测量绘制、显存传输、同步等待和实际交付帧间隔。
3. 按瓶颈选择减少重绘、A8、DMA/PPA、缓存背景、内部SRAM分块或双缓冲。
4. 核实缓存一致性和缓冲所有权，让 VSYNC 调度与 LVGL 定时器协作。
5. 清理对象、动画、任务、定时器及临时内存；允许完全熄屏时再关闭显示链路，并保留恢复路径。
6. 独立验收节拍、完整区间FPS、阶段时序、画面一致性、内存与空闲CPU。

入口为 [SKILL.md](SKILL.md)，详细方法在 [references](references/)。案例中的硬件、依赖补丁和定时器设定必须在目标项目重新验证，不保证任意负载均达60FPS。

## 时间戳分析

Python 3.10+，仅依赖标准库。CSV 含 `timestamp_us` 列，或输入带 `[SPLASH_FRAME_TIMES] us=...` 的日志。

```sh
python scripts/analyze_frames.py frames.csv --target-fps 60 --expected-span-ms 4800 --output result.json
python scripts/analyze_frames.py serial.log --run 2 --target-fps 60 --output result.json
python -m unittest discover -s tests -v
```

多次播放日志必须指定 `--run`。默认平均节拍容差0.2%，最大帧间隔不得超过目标周期的1.08倍。退出码：0为节拍接受、1为不达标、2为输入错误。未指定覆盖时长时显示 `NOT_CHECKED`。

**脚本PASS仅证明输入时间戳的节拍及已请求的覆盖检查。** 它不验证打点语义、真实屏幕扫描、视觉一致性、退出释放或完整L2验收。
