# 测量与验收

## 事件语义先于公式

查看实际flush端口：调用返回可能只是入队；FLUSH_FINISH也可能只表示LVGL提交结束。仅在已核实其对应阻塞DMA/VSYNC交付时，用它统计实际完成帧。异步驱动应在合适的完成回调或栅栏处打点；面板扫描中重复显示旧缓冲不算新渲染帧。

在动画关键路径只写入预分配时间戳数组和计数器；打印、格式化和报告放到测量结束后。数组溢出、日志丢失、重置或时间戳回绕必须显式标记。默认不剔除慢帧；预热、测量起止和例外策略要事先定义。

同时记录三种量：

- 连续帧节拍：`(N-1)*1e6/(last_us-first_us)`；查看中位数、P95、最大间隔及约两帧的间隔。
- 完整区间FPS：`完成帧数/测量区间秒数`，包含首帧等待和清理尾部。不能用首尾帧时间代替整个区间。
- 250ms等短窗口计数：会出现整数帧量化，59.x/60.x不必然代表掉帧；同时看逐帧数据。

60Hz目标对应约16666.7us。检查覆盖是否包含所有昂贵阶段，而不是只采集最后静态画面。颜色层混合、缩放、扫光、淡出都应在覆盖内。

## 附带脚本

仅依赖Python标准库。CSV格式：

```csv
timestamp_us
10000
26667
43333
```

或日志中单行：`[SPLASH_FRAME_TIMES] us=10000,26667,43333`。多次播放时必须指定`--run`，脚本不会静默选取最好的一次。

```sh
python scripts/analyze_frames.py frames.csv --target-fps 60 --expected-span-ms 4800 --output result.json
python scripts/analyze_frames.py serial.log --run 2 --target-fps 60 --output result.json
python -m unittest discover -s tests -v
```

默认节拍误差允许0.2%，最长间隔为目标周期的1.08倍；均可配置且应记录。`expected-span-ms`指首尾有效帧跨度下限，允许最后一帧量化一个周期；不是上电到完成时长。未提供则覆盖为NOT_CHECKED。脚本只给节拍判定，并明确其他验收未验证；缺失、重复、逆序或超大整数时间戳为ERROR。

## 其他独立验收

- 视觉：固定时刻的LVGL快照与同时间HTML/设计参考比较；颜色量化、字体和混合顺序差异单独说明。
- 时序：实际阶段开始时间与设计值比较，不能挪动日志时间使其达标。
- 内存：在同样初始化/缓存预热状态下对比，检查资源计数并多次复开；首次退出后FreeRTOS延迟回收与长期下降应区别看待。
- 空闲CPU：说明是整机还是任务口径，保留后台任务清单；0.01%整机CPU不等于芯片绝对零开销。
- 外部画面：花屏、闪白、方向和居中仍需真实屏幕或相机证据。
